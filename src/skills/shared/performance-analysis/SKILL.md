# 通用性能分析

## 前置检查

1. 读取 `AGENTS.md`，确认当前 `techStack`。
2. 若存在匹配 profile 的性能 skill，优先叠加读取：
   - 后端 profile：`backend-performance-analysis`
   - 前端 profile：`frontend-performance-audit`
3. 没有证据时只输出排查计划，不直接建议结构性改造。

## 分析流程

1. 明确场景：入口、操作步骤、数据规模、出现频率和用户可感知影响。
2. 建立基线：耗时、调用次数、渲染次数、内存/CPU、网络或日志指标，至少给出可验证来源。
3. 归因瓶颈：区分请求、计算、渲染、I/O、锁竞争、调度、资源体积或外部依赖。
4. 评估方案：计算收益、复杂度、资源成本、兼容影响和回滚成本。
5. 先给低风险高收益改法；高风险结构调整必须标注前提并等待用户确认。

## 输出格式

1. 分析对象与场景
2. 证据与基线
3. 瓶颈判断
4. 优化方案与优先级
5. 验证方式与回滚
