# 前端性能审计

## 前置检查

1. 读取 `AGENTS.md`，确认 `techStack` 为 `frontend-vue3` 或 `frontend-react-umi`。
2. 若不是前端 profile，跳过本 skill，使用通用 `performance-analysis`。
3. 明确卡顿页面、操作步骤、数据规模和出现频率。
4. 优先收集浏览器性能面板、Network、渲染次数、日志或用户可复现证据。

## 审计流程

1. 识别症状：首屏慢、交互慢、滚动慢、输入慢或请求慢。
2. 区分瓶颈：请求、计算、渲染、响应式、调度、样式或资源体积。
3. 找主要放大因素：重复请求、重复计算、深监听、大对象响应式、复杂插槽、全量刷新。
4. 先给低风险优化，再评估结构拆分或懒加载。
5. 每条建议都写清证据、方案、验证方式和回滚成本。

## 优先级

- P0：去重请求、缓存派生数据、减少无效刷新、修正监听源。
- P1：拆分重组件、懒加载非首屏弹窗/Tab、降低状态粒度。
- P2：调整架构或数据模型；仅在证据充分且用户确认后推进。

## 输出格式

1. 症状
2. 可能瓶颈
3. 证据
4. 最小改动方案
5. 预期收益
6. 副作用/风险
