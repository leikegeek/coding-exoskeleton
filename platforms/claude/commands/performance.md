# /performance — 独立性能分析入口

当用户输入 `/performance` 时，启动独立性能分析流程。该入口用于对当前项目、指定模块、指定场景或本地变更执行性能分析，并输出标准性能分析报告。

## 触发方式

- `/performance` — 对当前项目或当前上下文执行通用性能分析
- `/performance <场景描述>` — 针对指定业务场景、接口、页面或操作路径分析
- `/performance @<文件或目录>` — 针对指定文件、模块或目录分析
- `/performance --local <baseRef>...<headRef>` — 针对本地分支 diff 分析性能影响

## 定位

`/performance` 是 `/code` B3 性能检查能力的独立入口：

```text
/code B3
  → verification-loop
  → performance-analysis
  → 性能扫描摘要进入交付验证上下文

/performance
  → 明确分析对象和场景
  → performance-analysis
  → 输出独立性能分析报告
```

入口差异只体现在触发方式和输出形态；性能分析标准统一由 `performance-analysis` skill 定义，并按当前项目画像叠加 profile 专项性能 skill。

## 预检步骤

### 1. 项目画像检查

检查当前项目是否存在 `AGENTS.md`：

- 存在：读取技术栈、架构模式、模块结构和激活规则范围。
- 不存在：不强制初始化，但应提示性能分析会缺少项目特有技术栈信息；用户可选择先执行 `/init`。

### 2. 建立任务契约

- 模式：设计模式 / 只读分析
- 目标：对指定对象执行性能分析并输出标准报告
- 允许写入路径：默认不写入；用户要求文件形式时仅写入 `docs/performance/`
- 禁止项：不修改业务代码、不创建分支、不提交 commit、不执行破坏性压测或 DoS 类操作
- 验收标准：输出分析对象、证据与基线、瓶颈判断、优化优先级、验证方式和回滚策略

## 执行流程

1. 解析用户输入，明确分析对象：
   - 项目整体、指定模块、指定接口、指定页面、指定操作路径或本地 diff。
   - 若对象不明确，优先按当前上下文和最近变更继续；只有缺少会改变结论的关键信息时才询问。
2. 读取 `performance-analysis` skill，执行通用性能分析流程。
3. 根据 `AGENTS.md` 中的 `techStack` 叠加匹配 profile 的性能 skill：
   - 后端 profile：`backend-performance-analysis`
   - 前端 profile：`frontend-performance-audit`
4. 收集证据与基线：
   - 可使用代码结构、调用链、构建配置、日志、测试结果、监控指标或用户提供的数据。
   - 没有证据时，只输出排查计划和待采集指标，不直接给结构性改造结论。
5. 输出标准性能分析报告。

## 输出要求

- 默认直接在对话中输出 Markdown 报告。
- 用户需要文件形式时，保存到 `docs/performance/performance-report-YYYYMMDD.md` 或 `docs/performance/<需求编号>-performance-report.md`。
- 对高风险结构调整、压测外部服务、批量请求或可能影响环境稳定性的动作，必须先获得用户明确确认。
